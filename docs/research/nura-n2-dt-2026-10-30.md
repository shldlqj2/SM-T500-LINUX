# N2 실행 기록 — SM-T500 SD·USB DT와 공식 LTS 연결

## 결과와 남은 관문

2026-10-30 SM-T500 Wi-Fi 전용 시험 DTS와 DT 패키지를 만들고, 공식 `linux-postmarketos-lts=6.18.35-r0`을 연결한 기기 패키지로 `pmbootstrap install --no-image`를 완료했다. N1에서 실패했던 kernel/flavor 검사와 `mkinitfs`가 종료 0으로 통과했다. DT는 로컬에서 컴파일했고 kernel·모듈은 공식 APK에서 설치했다. 커널 자체를 로컬에서 컴파일한 결과가 아니다.

**N2는 오프라인 준비 부분 완료다.** kernel·DTB·initramfs·모듈·383개 패키지의 대응과 해시·저장소 신뢰 경로를 검사했다. boot.img·N2 ext4 rootfs 파일은 생성하지 않았다. DT 선택·reserved-memory·최종 boot 배치·SD 식별/실패 정책이 남아 있으므로 N2 전체/M2 합격이나 실기기 부팅 성공으로 표시하지 않는다. 실기기 조사·기록·재부팅·SD 쓰기·복구 시험은 미실행이다.

이전 세션은 산출물 검증 중 실행 서비스 오류로 끝났고 HANDOFF는 N1 상태였다. 재개 시 파일을 우선해 기존 결과를 대조했다. 재개 관측에서는 작업 경로 mount·관련 빌드 프로세스·qemu-aarch64 binfmt 등록이 없었다. 과거 install 로그의 `chroot is still active`는 당시 상태이며 현재 상태가 아니다.

## 선별 이식과 지원 공백

순정 boot DTB 11개·DTBO 20개의 정적 자료에서 Bengal 후보를 분류했다. `boot-dtb-000.dtb`와 `dtbo-013.dtb` 등 후보의 SD·USB 연결을 읽었으며, 이 번호를 실기기의 선택 결과로 확정하지 않았다. 선택 근거·추출 원문은 `private/nura/n2/stock-board-facts.json`과 `rea/`, 기존 `private/firmware/T500XXS8CXG1/`에 있다.

| 항목 | 채택·수정·제외와 이유 | 현재 한계 |
| --- | --- | --- |
| SM6115·PM6125 공통 정의 | 공식 Linux 6.18.35 DTSI 사용 | 실기기 부품/메모리 배치 미대조 |
| 외장 SD | L22 2.96V, L5 1.8~2.96V, 카드 감지 GPIO 88을 mainline binding으로 표현 | 감지 극성·전압 전환·SD 접근은 정적 후보 정보 |
| SD bias | downstream `vdd-io-bias-supply`를 복사하지 않고 L7 1.256V always-on 시험 가설로 표현 | binding 대응·전원 동작을 실기기에서 확인해야 함 |
| SD pinctrl | 기존 downstream 속성 대신 mainline state 사용, data drive-strength 16mA 후보 반영 | 초기 drive-strength·카드 호환성 미검증 |
| USB | L4/L12/L15 공급과 SM6115 QUSB2 PHY, high-speed peripheral 구성 | downstream PHY tuning·충전/role 전환·USB 열거 미검증 |
| 초기 모듈 | `modules-initfs`에 `phy-qcom-qusb2` 추가 | 포함 검사는 완료, 실제 probe/통신은 미검증 |
| 기존 Tab A7 포트 | 기기/driver 비교 자료로 사용, 수동 symbols·오래된 config·offset은 미도입 | 기존 포트 기능표를 본 기기 증거로 사용하지 않음 |
| LTE/모뎀 | MPSS·IPA·셀룰러 서비스를 활성화하지 않음 | 공통 DTSI의 비활성 노드·메모리 예약은 유지. Wi-Fi 공유 무선 의존성은 별도 분석 |
| 화면·터치 | 이번 DTS에서 활성화하지 않음 | panel/전원/터치 변형 미확인. 공식 config에서 simpledrm·FB_SIMPLE은 꺼져 있음 |
| Wi-Fi·Bluetooth | firmware·보정 파일·초기화는 미도입 | driver 옵션 존재만으로 지원 완료를 판정하지 않음 |
| 다른 모델 자료 | upstream Lenovo DT는 binding 비교군으로만 컴파일 | 비교 DTB·framebuffer 주소·GPIO 45 우회 설정은 SM-T500 세트에서 제외 |

새 [DTS](../../ports/dtb-samsung-gta4lwifi/sm6115-samsung-gta4lwifi.dts)는 `GPL-2.0-or-later OR BSD-3-Clause`이며 공통 DTSI의 원래 SPDX·저작권을 유지한다. 순정 DTB/DTBO 원문·firmware·보정 데이터는 공개 source나 APK에 넣지 않았다. [D015](../decisions.md)의 오프라인 평가 범위를 따른다.

## DT·설정·initramfs 검증

`dtc` 빌드와 source SHA-512 검사는 통과했다. 호스트에서 만든 SM-T500 DTB와 APK 설치 후 `/boot`의 DTB는 크기·SHA-256이 같다. 최초 schema 검사에서 카드 감지 pinctrl의 표현 오류를 수정했다.

최종 전체 schema 검사에는 각 DT의 upstream `gpu@5900000`에서 `reg-names` 관련 진단 2개가 남았다(`cx_dbgc` 순서·목록 길이). 수정하지 않은 upstream Lenovo 비교 DT에서도 같은 2개가 나온다. 명령 종료 0을 진단 없음으로 해석하지 않으며 **전체 binding 검사 무경고 통과로 표시하지 않는다.** 로그는 `logs/dt-schema-v2.log`다.

설치된 `/boot/config`와 고정 recipe의 활성 설정을 비교했다. 차이는 recipe의 `CONFIG_CC_CAN_LINK=y`가 설치 config에 없는 1개다. 설치 config의 compiler 표기는 Alpine clang 22.1.3·rustc 1.96.0이다. 이는 패키지에 기록된 빌드 정보이며 이번 WSL에서 사용한 kernel toolchain이 아니다. APK 메타데이터의 producer commit은 `-dirty`라 정확한 생산자 source commit·동일 빌드 재현은 미검증이다. 소스 버전·설정 유사성과 바이너리 재현을 구분한다.

SD 접근의 MMC/SDHCI_MSM·EXT4와 SM6115 pinctrl/GCC/interconnect·RPM/SMEM, USB DWC3/QCOM·GADGET은 built-in이다. QUSB2 PHY는 모듈이며 release와 vermagic이 `6.18.35`로 대응한다. `CGROUPS`, `MEMCG`, `CGROUP_PIDS`, `CGROUP_BPF`, namespace·seccomp 주요 옵션도 켜져 있다. 이 검사는 systemd/Docker 런타임 시험을 대체하지 않는다.

initramfs는 gzip/newc 347개 항목이다. `/init`, `usr/lib/modules/initramfs.load`, 대응 PHY 모듈과 USB gadget 의존 모듈을 확인했고 PHY 바이트가 rootfs와 일치했다. 계정 비밀번호·machine-id·SSH 개인 키 이름은 이 archive에서 발견하지 못했다. 전체 rootfs의 비공개 로그인 설정까지 공개용으로 정리한 것은 아니다.

표준 initramfs의 USB network 기본값은 NCM이고 RNDIS fallback 및 debug shell의 ACM 경로가 있다. 실제 Windows 호환성·열거는 미검증이다. 표준 root 탐색에는 `pmOS_root` label과 UUID/path 경로가 있으므로 실제 SD UUID 고정·SD 부재/오류 시 내부 저장소로 전환하지 않는 정책을 후속 검사해야 한다. N1의 `NURA_N1_ROOTFS` 이미지에는 N2 모듈이 없으므로 이 세트의 대응 rootfs로 사용하지 않는다.

## kernel 형식과 산출물

공식 `/boot/vmlinuz`는 EFI zboot 형식이다. 고정 Linux 소스의 `drivers/firmware/efi/libstub/zboot-header.S`와 대조해 offset 48,872·길이 18,107,697의 gzip payload를 추출했다. 해제한 Image의 ARM64 magic은 `41524d64`, text_offset은 0, image_size는 51,118,080 bytes다. `Image`·`Image.gz`는 형식 분석용이며 Samsung bootloader의 수용·최종 배치를 검증한 것이 아니다. 관측되지 않은 boot offset을 넣어 boot.img를 만들지 않았다.

## 실행 명령·로그와 재개 검증

실행 cwd는 위 WSL N2 경로이고 문서/Windows 검사는 저장소 루트다. 상세 argv·시각·종료 코드는 `private/nura/n2/pmb-*.json`에 있다. 비밀번호 인수는 가렸으며 원본 상세 로그에는 생성용 정보가 있으므로 공개하지 않는다.

저장소 신뢰 검사는 allow-untrusted 없이 서명된 index와 APK checksum 연결을 재검증했다. 재설치한 kernel/config/System.map·DTB·PHY 모듈도 기존 트리와 바이트가 같다. 이는 개별 APK 서명자의 독립 신원 검증이나 source 재빌드가 아니다.

재개 시 Windows에서 해당 이름의 Samsung/Android/ADB/MTP 장치·adb/odin/heimdall 프로세스·PATH의 adb를 찾지 못했다. 이 제한된 호스트 조회로 태블릿의 실제 OS·모드·root 상태를 확정하지 않는다. 문서/패키지 source 무결성·상대 링크·내용 검사와 최종 프로세스 상태는 `private/nura/n2/final-validation.json`에 기록한다. 관련 없는 수집기 테스트·kernel 전체 빌드·실기기 시험은 실행하지 않았다.
